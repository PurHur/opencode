Run several subagent steps as one workflow. Each step runs in its own fresh subagent; results flow forward automatically.

## Easiest form (use this)
Pass `steps` as a plain list of strings. Each string is one task. It runs after the previous one and automatically receives the previous result.

  workflow({
    "description": "research topic",
    "steps": [
      "Research the most active smart contracts on Ethereum and list their addresses",
      "For each contract from the previous step, scan the source for vulnerabilities",
      "Write a short report of the findings"
    ]
  })

## Run steps in parallel
Make a step an array of strings. Those run at the same time, and the next step receives all of their results.

  workflow({
    "description": "scan chains",
    "steps": [
      ["Scan Ethereum contracts", "Scan Base contracts", "Scan Arbitrum contracts"],
      "Combine the findings from all chains into one report"
    ]
  })

## When to use
- Multi-part work you can plan up front: research several things, inspect several targets, then combine.
- You want it executed in one go instead of issuing task calls one at a time.

## When NOT to use
- A single piece of delegated work — use the task tool.
- Work where you must read each result yourself before deciding the next step.

## Advanced form (only if you need an explicit graph)
Instead of a string, a step may be an object: `{ "prompt": "...", "agent": "general", "id": "x", "depends_on": ["y"] }`. Use `{{y}}` inside a prompt to inject the result of step `y`. Ids are auto-generated when omitted.

## Rules
- Max 16 steps, concurrency default 4 (max 8).
- Each step is a fresh subagent with no memory of the others — put everything it needs in its text.
- If a step fails, its dependents are skipped and the other results are still returned; check the per-step states in the output.

## Reliability (optional)
- `retries` (default 2, max 5, 0 disables): retry a step that fails with a transient error such as "loading model", 503, overloaded, connection reset, or timeout, using exponential backoff. Non-transient errors fail immediately.
- `step_timeout_seconds` (default 0 = no limit, max 3600): cancel a step and mark it a timeout error if it runs longer than this. Useful for a slow or flaky local model that can hang.
