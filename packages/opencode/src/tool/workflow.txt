Run a fixed set of subagent steps as a dependency graph (DAG). Steps without dependencies run in parallel; a step runs only after every step it depends on has finished.

## When to use
- Multi-part work that splits into independent pieces (research several areas, inspect several packages, review several files) and a final step that combines them.
- You already know the whole plan up front and want it executed deterministically instead of issuing task calls one at a time.

## When NOT to use
- A single piece of delegated work — use the task tool.
- Work where each next step depends on reading the previous result yourself before deciding what to do.

## Parameters
- `steps[].id` — unique short identifier, referenced by other steps.
- `steps[].agent` — subagent type to run the step (defaults to `general`).
- `steps[].prompt` — the instructions for that step. Use `{{otherId}}` to inject the final text of a step listed in `depends_on`.
- `steps[].depends_on` — ids that must complete first.
- `concurrency` — max steps running at once (default 4, max 8).

## Rules
- Max 16 steps. Ids must be unique, dependencies must exist, and the graph must not contain cycles.
- Each step runs in its own fresh subagent session with no memory of the others — put everything a step needs in its prompt.
- If a step fails, its dependents are skipped and the remaining results are still returned; read the per-step states in the output before concluding.
